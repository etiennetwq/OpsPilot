# 完成后再学习：代码与面试重点

作品已经可运行。下面是边投递边掌握代码的路线，不是继续开发的前置步骤。

## 第一轮：能演示与解释

从 README 三分钟演示走一遍。必须能解释“公开真实日志”与“自己生产部署”的区别，以及 EventId 与根因标签的区别。面试时明确说这是独立研究作品，没有生产接入。

## 第二轮：读一条完整请求

1. api.py 的 Request 限定输入和方法。
2. agent.py 建立日志、文档两套索引，diagnose 选择检索方式。
3. retrieval.py 对 BM25 和 dense 做 RRF；看排序 tie-break。
4. tools.py 通过固定 SELECT 读取相邻行及统计。
5. llm.py 组装证据、调用 API、验证 JSON 与引用；API 失败回退。
6. evaluate.py 读取独立标签，计算任务成功及逐题失败。

## 常见面试题与回答要点

|问题|回答应覆盖|
|---|---|
|为何不用纯向量？|日志有精确标识符，BM25 保留词项；向量可处理局部变化。小样本当前没有证明 Hybrid 优于向量。|
|向量是什么？|默认字符 TF-IDF 经 SVD 的本地 dense 表示；不是神经 embedding。可配置本地 SentenceTransformer，但此次未测。|
|为何 RRF？|两套分数不可直接比较，以排名相加；常数 60；不输出概率。|
|为什么算 Agent？|v0.2 由真实模型通过 tool_calls 选择只读工具；程序校验并执行。原固定工作流作对照，不提供 shell 或自动修复。|
|如何防幻觉？|提供来源、拒答、引用白名单、区分假设；这些不保证语义蕴含，仍需人工复核。|
|如何防提示注入？|证据仅当数据，工具无任意执行入口；模型可能仍输出不当文本，不能声称完全免疫。|
|如何做评测？|上游 EventId 定义日志相关性，人工定义文档主题，保存逐题结果；15 题小样本，有模板偏差，没有 RCA 标签。|
|为什么 Recall 很低？|分母是某事件全部重复日志行，top5 最多取5行；Hit@5 与 Recall@5 衡量不同问题。|
|Token/费用怎么来？|provider usage 与配置价格；无调用为0，失败或未报价为未知；本次未测真实 API。|
|企业化还差什么？|独立事件标签、实时接入、认证、权限隔离、并发和压力测试、监控与专家审阅。|

## 两个项目的互补叙事

原 LLM Security Audit Gateway 讲模型应用的安全审计与控制；OpsPilot 讲数据溯源、证据检索、只读工具编排、可观测输出和可复现评测。分别演示，各有仓库，避免讲成同一项目换名字。

简历只能写你能实际讲清并运行的功能。不要写“线上根因准确率”“服务企业生产系统”“降低排障工时”或未经真实 API 测量的提升数字。OpsPilot 可引用 reports 内本机实测；原项目指标仍以原仓库报告为依据。


## 新增工具调用面试重点

从 tool_agent.py 的 REGISTRY → definitions → run 读完整回路。解释 assistant tool_calls 与 tool role/tool_call_id 如何配对，为什么未知工具和重复ID要拒绝，为什么最终答案也走受校验的工具。严格参数校验由本地程序保证，不依赖模型遵从提示；这不等于内容语义保证。

真实调试曾发生多次工具查完后最终JSON提交失败，说明连通API与任务完成是两个验收点。阅读新评测中的失败，分别解释模型选择错误、格式/长度错误、预算停止和数据不支持。Token使用服务商usage，费用缺少准确计费信息时保留未知。
